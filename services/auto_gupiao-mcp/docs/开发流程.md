# 开发流程

本项目默认采用 Pull Request 开发流程，以保证每次修改都经过 GitHub Actions 全量回归。

## 日常开发流程

1. 从 `main` 创建功能分支。
2. 在功能分支开发并提交，提交备注使用中文。
3. 创建 Pull Request 到 `main`。
4. 等待 GitHub Actions `Go CI` 完成。
5. 如果失败，查看失败 step 和日志，修复后重新提交。
6. 如果成功，合并 Pull Request。
7. 合并后确认 `main` 最新提交。

## 为什么不用直接推 main

直接推 `main` 时，当前 GitHub connector 对 push 触发的 Actions run 查询不稳定。Pull Request 触发的 Actions run 可以通过工具读取：

- workflow run 状态。
- job 状态。
- step 状态。
- 失败日志。

因此后续默认使用 PR 流程。

## CI 覆盖范围

`.github/workflows/go-ci.yml` 当前覆盖：

- Go 格式检查。
- 全量单元测试。
- CLI 编译。
- select 命令 smoke test。
- backtest 命令 smoke test。
- simulate 命令 smoke test。
- plan 命令 smoke test。
- paper 命令 smoke test。
- report 命令 smoke test。
- daily 命令 smoke test。

## 本地建议命令

```bash
gofmt -w .
go test ./...
go build ./cmd/autogupiao
```

## 生成文件约定

以下目录为本地生成内容，不应提交：

- `data/cache/`
- `data/bars/`
- `data/account/`
- `reports/`

临时测试文件也不应提交。
