# MyGithut12 需求文档

## 1. 背景

MyGithut11 已具备安全的 GitHub 读取、写入、PR、Issue、CI、Artifact、Release 和部署编排，但 AI 在代码理解上仍依赖逐层列目录和逐文件读取。用户还会同时打开多个聊天窗口，让不同 AI 在不同分支开发；如果没有不可变索引、工作区租约和跨分支重叠分析，容易出现索引串线、同分支并发写、分支漂移和重复劳动。

MyGithut12 必须同时解决“检索速度”和“多窗口并发开发正确性”，不能只增加一个全文搜索接口。

## 2. 目标

1. 在精确 Commit 上快速定位文件、文本、语义候选、符号、定义、引用、实现和调用关系。
2. 支持多个聊天窗口在不同工作区和分支并发开发，索引和写租约互相隔离。
3. 新分支与基础 Commit 相同时立即复用索引；提交后仅增量重建变化文件和受影响关系。
4. 在修改前后提供补丁分析、影响范围、受影响测试、契约变化和上下文包。
5. 所有结果可追溯到 `repository + commit_sha + tree_sha + blob_sha`。
6. 保留原 118 个工具兼容性，新增 36 个工具，总数达到 154。
7. 不暴露任意 Shell、Git URL、服务器路径、SQL、Secret 或自动部署能力。

## 3. 非目标

- 不把语义相似度当成真实定义、引用、实现或调用关系。
- 不执行调用方提交的任意命令。
- 不自动合并、自动发布或自动删除分支。
- 不承诺所有语言都有完整关系能力；不支持时必须返回稳定错误。
- 不依赖聊天平台提供隐式“当前分支”；每次操作都使用工作区或显式 Commit。

## 4. 主要使用场景

- 多窗口分别修复设备、支付和国际化功能，各自使用唯一工作区和分支。
- 查询方法定义、接口实现、调用方、类型层级和相关测试。
- 根据 API 路径追踪 Router、Handler、Service、Repository 和迁移。
- 在提交前分析补丁是否可应用、是否产生诊断或破坏契约。
- 比较两个 Commit，判断影响模块、API、数据表、配置和测试。
- 发现两个活动分支修改了相同符号、迁移或契约，提前告警。
- 自动读取适用于目标路径的 AGENTS、CLAUDE、CONTRIBUTING 和 README 规则。
- 为开发、评审和交接生成带证据的最小上下文包。

## 5. 功能需求

### FR-001 精确版本身份

所有读取、搜索和分析必须解析到完整 40 位 Commit SHA，并返回 Tree SHA。文件结果返回 Blob SHA。ref 和 Commit 不一致时失败关闭。

### FR-002 不可变索引

索引键必须包含仓库、Commit、Tree 和索引版本。已完成索引只读，不因分支移动而原地更新。

### FR-003 增量索引

构建策略支持 `auto / incremental / full`。增量构建必须记录基础 Commit、变化文件、复用文件、重建文件和受影响关系。基础索引不可用时，`auto` 可回退全量，`incremental` 必须报错。

### FR-004 构建并发与长轮询

相同目标 Commit 的并发构建去重。支持状态查询、最长 55 秒等待、安全取消、失败恢复和僵尸任务回收。

### FR-005 开发工作区

工作区包含唯一 ID、仓库、分支、基础分支、基础 Commit、HEAD、Tree、Revision、状态、租约、声明范围、索引 Pin、PR 和 CI 关联。

### FR-006 工作区租约

默认一个活动工作区独占一个分支写入。租约有 TTL、续期和 CAS Revision。多个工作区可读同一分支，但不能同时写。

### FR-007 分支漂移

分支被其他窗口、人工或 GitHub 操作移动时，工作区标记为 drifted。所有写入在刷新并重新确认前必须失败。

### FR-008 写工具集成

现有写工具增加可选 `workspace_id` 和 `expected_workspace_revision`。策略启用后，AI 分支写入必须校验工作区租约、Revision、expected HEAD 和 GitHub HEAD。

### FR-009 开发范围与重叠

工作区可声明路径、符号、API、表、迁移和配置范围。系统必须比较声明和实际变化，返回文件、符号、契约和迁移重叠证据。

### FR-010 工作区同步规划

必须能比较工作区基础 Commit、当前基础分支和工作区 HEAD，分析 ahead/behind、三方差异、潜在冲突和需要重建的索引；只做计划，不自动 rebase。

### FR-011 目录树、文件搜索和批量读取

支持受限递归树、路径搜索、扩展名过滤、深度、数量、总字节和游标。单个文件失败不能掩盖其他批量结果。

### FR-012 文本搜索

支持普通文本和受限正则，返回路径、Blob、行范围、匹配区间、上下文、分页和截断。

### FR-013 语义候选检索

语义搜索只返回候选，必须带精确源码证据和评分，并标记非权威。语义结果不能用于伪造定义、引用或调用边。

### FR-014 符号目录

首批支持 Go、Python、TypeScript、JavaScript 和 Vue。稳定 `symbol_id` 必须区分包、类型、文件和同名符号。

### FR-015 定义、引用、实现和类型层级

语言服务或语法分析必须提供可靠证据。无法可靠判断时返回 unavailable，不得退化成文本同名匹配并宣称可靠关系。

### FR-016 调用层级

支持 callers、callees 和 both，默认深度 2，限制节点和边，循环调用去重并标记。

### FR-017 诊断

支持符号或文件范围的解析、类型和语言服务诊断。不得接受任意编译命令或可执行参数。

### FR-018 符号历史

在受限 Commit 数量和时间范围内返回创建、重命名、签名变化和删除事件，每项绑定 Commit 和文件证据。

### FR-019 依赖图

支持包、模块和目标符号依赖，区分 import、调用、实现和生成关系，限制深度和节点数。

### FR-020 仓库指令解析

按路径解析 AGENTS、CLAUDE、CONTRIBUTING、README 和仓库策略，返回来源、适用范围、优先级和冲突。

### FR-021 上下文包

仓库上下文包和变化上下文包都必须可审计，每个文件或片段有选择理由，并遵守文件数和总字节限制。

### FR-022 变化影响

两个 Commit 的影响分析必须覆盖符号、依赖、API、数据表、迁移、配置、测试和风险，并说明完整性和缺失分析器。

### FR-023 补丁分析

对补丁进行纯预览应用，验证基础 Commit、路径、上下文和 Blob；返回诊断、影响、测试和契约变化，不写 GitHub。

### FR-024 受影响测试

根据差异、补丁、文件或符号选择测试候选，区分直接、包级、集成和回归测试，给出证据和置信等级。

### FR-025 契约变化

检测 OpenAPI/API、数据库迁移、事件 Schema、配置、权限、CLI 和公共符号变化，区分 breaking、compatible 和 unknown。

### FR-026 版本与发现

服务名为 `MyGithut12`，版本为 `12.0.0`。运行时必须发现 154 个唯一工具，Manifest、Connector 和 capability 一致。

### FR-027 安全与资源限制

所有仓库请求经过白名单。禁止任意 URL、主机、路径、Shell 和 Secret。正则、语义查询、图深度、历史范围、构建并发、CPU、内存、磁盘和超时均有硬限制。

### FR-028 可观测性

记录低基数构建、查询、工作区、租约冲突、索引复用、重建文件、截断、延迟和错误码。日志不记录文件全文、凭据或大段代码。

## 6. 数据一致性约束

- GitHub 是源码事实来源，索引是可重建缓存。
- 工作区状态必须使用共享数据库，不能保存在单个进程内存。
- 分支名只用于导航，Commit 和 Tree 才是索引身份。
- 写成功、工作区 HEAD 更新和索引请求必须具有可恢复的一致性记录。
- 活跃工作区 Pin 的索引不能被过期清理。
- 查询开始后固定 Commit，不能在一次响应中混合分支移动前后的数据。

## 7. 成功标准

- 客户端真实发现 `MyGithut12` 和 154 个唯一工具。
- 三个以上聊天窗口在三个分支并发开发时，索引、租约、范围和写入互不串线。
- 同一分支双写时至少一个请求以稳定冲突错误失败，不发生覆盖。
- 新分支相同 Commit 的索引复用 P95 小于 1 秒；小范围提交增量索引 P95 目标小于 15 秒。
- 约 50 MiB 热索引仓库：文本和符号搜索 P95 小于 3 秒，定义和引用 P95 小于 5 秒，上下文和影响分析 P95 小于 10 秒。
- 原 118 个工具回归、安全测试、并发测试和两个真实仓库冒烟全部通过。
