# MyGithut12 需求文档

## 1. 背景

现有 MyGithut11 能安全读取和写入 GitHub 文件，也覆盖 PR、Issue、CI、Artifact、Release 和部署编排，但缺少精确 Commit 上的全仓文本搜索、符号定义、引用和调用关系。AI 查找一个方法时只能依赖目录判断后逐文件读取，调用次数多，并容易漏掉同名实现、测试和真实调用方。

客户端工具发现以已注册的 MCP 命名空间和 Schema 为准，因此本次新增接口必须作为 MyGithut12 发布，不能只在旧服务内部增加不可发现的函数。

## 2. 目标

1. AI 能在不克隆到调用方本地的情况下，基于精确 Commit 快速定位文件、文本和符号。
2. 所有结果可追溯到 `repository + commit_sha + tree_sha + blob_sha`。
3. 索引落后、缺失或失败时明确报错，不使用旧索引冒充当前代码。
4. 保留现有 118 个工具兼容性，新增 12 个工具，总数达到 130。
5. 不引入任意 Shell、任意 Git URL、任意服务器路径或 Secret 读取能力。

## 3. 非目标

- 不执行用户提交的任意命令。
- 不提供任意 SSH、数据库 SQL 或主机文件读取。
- 不把向量相似度结果当成真实定义或引用。
- 不在本版本实现自动修改、自动合并或自动部署。
- 不承诺所有编程语言都支持引用和调用层级；不支持时必须明确返回错误。

## 4. 主要使用场景

- 找到某个方法的定义、接口实现和测试。
- 根据 API 路径追踪 Router、Handler、Service、Repository。
- 查找字段名、错误码、表名或配置项在全仓的使用位置。
- 一次读取多个关联文件，建立同一 Commit 的代码上下文。
- 在修改前确认符号引用和潜在影响范围。
- 为代码评审生成带选择理由的最小上下文包。

## 5. 功能需求

### FR-001 精确版本

所有新工具必须接收或解析到完整 40 位 Commit SHA。返回值必须包含 `resolved_commit_sha` 和 `tree_sha`。如果请求中的 ref 与 commit 不一致，返回 `INDEX_COMMIT_MISMATCH`。

### FR-002 索引生命周期

必须支持查询索引状态、请求构建和查询任务。相同仓库和 Commit 的并发构建必须去重；索引键至少包含仓库、Commit、Tree SHA 和索引版本。

### FR-003 目录树和文件搜索

必须支持受限递归树、路径搜索、扩展名过滤、深度、数量限制和游标分页。禁止无上限返回整仓。

### FR-004 批量读取

必须支持一批明确路径的读取，并返回每个文件的独立结果。必须限制文件数量和总字节数，不能因为一个路径不存在而丢失其他成功结果。

### FR-005 文本搜索

支持普通文本和受限正则，支持大小写、路径范围、上下文行和分页。每条结果包含 Blob SHA、行范围和精确匹配区间。

### FR-006 符号搜索

至少支持 Go、Python、TypeScript、JavaScript 和 Vue 的符号目录。`symbol_id` 在同一 Commit 和索引版本内稳定，并能区分同名符号。

### FR-007 定义和引用

定义查询必须接受 `symbol_id` 或文件位置。引用必须区分读、写、调用、实现、类型引用和未知引用；无法可靠判断时不得猜测。

### FR-008 调用层级

支持 caller、callee 和 both，深度默认 2，必须限制节点和边数量。循环调用必须去重并标记。

### FR-009 上下文包

上下文包必须是可审计的：每个文件或片段都有选择理由，不得偷偷加入未列出的内容。必须遵守文件数和总字节限制。

### FR-010 版本和发现

外部服务名为 `MyGithut12`，版本为 `12.0.0`。工具 Manifest、Connector 名称、能力返回和部署配置必须一致。

### FR-011 兼容性

原 118 个工具的名称和参数 Schema 不做破坏性修改。旧环境变量可在一个迁移周期内作为兼容回退，但能力返回必须指出实际来源。

### FR-012 安全

所有仓库请求继续经过 `ALLOWED_REPOSITORIES`。索引快照路径由服务端生成，调用方不得传入 Git URL、本地路径、命令或可执行参数。默认排除二进制、依赖目录、构建产物和敏感文件。

### FR-013 可观测性

记录低基数指标：构建数量、构建耗时、索引大小、查询次数、查询耗时、截断次数和错误码。日志不得记录文件全文、Secret 或大段代码片段。

## 6. 约束

- GitHub 是源码事实来源。
- 索引是可重建缓存，不得成为源码事实来源。
- 每个查询必须先验证仓库授权。
- 搜索结果必须有分页或明确截断标记。
- 索引服务故障不能影响原 118 个 GitHub/CI 工具。

## 7. 成功标准

- Connector 中能发现 `MyGithut12` 和 130 个唯一工具。
- 对已建立索引的中型仓库，热状态查询和文件搜索 P95 小于 1 秒，文本和符号搜索 P95 小于 3 秒，定义和引用 P95 小于 5 秒。
- 在 `frankichen/github_mcp` 与 `frankichen/sxt` 冒烟测试中，结果全部绑定正确 Commit。
- 旧工具回归测试全部通过。
- 安全测试证明无法传入任意路径、URL、Shell 或越权仓库。
