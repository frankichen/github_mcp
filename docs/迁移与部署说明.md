# MCP 与 CI 服务迁移说明

本仓库现在只包含 GitHub/MCP 控制端和私有部署 Worker，股票相关服务已经删除。

## 两端

- 控制端：`services/github-action-service`，可运行在本地、CI 机器或 Docker 中。
- 服务器端：`services/private-deploy-agent`，运行在 `root@de` 的 `/opt/private-deploy-agent`。

控制端创建或查询部署意图，服务器 Worker 从受控队列领取任务。Worker 不接受 MCP 参数中的任意 SSH 主机、Shell 命令或脚本路径。

## 迁移前保存

- 源码、requirements、Dockerfile 和示例配置；
- `/var/lib/private-ci/` 下的 CI/部署数据库；
- `/etc/private-ci/deploy-worker.env`，但只能放入密码管理器或受限备份，不能提交 Git；
- `/etc/systemd/system/private-deploy-agent.service` 及 drop-in 配置；
- 目标工作区的部署脚本、发布脚本和当前 release 状态。

## 原生 Ubuntu 恢复顺序

1. 安装 Git、Python、Docker、反向代理和必要的构建工具；
2. 克隆本仓库；
3. 部署 `github-action-service` 并验证健康检查；
4. 创建 `deployworker` 用户和 `/var/lib/private-ci`；
5. 安装 `services/private-deploy-agent/requirements.txt`；
6. 写入服务器本地 Secret 环境文件；
7. 安装并启动 systemd Worker；
8. 先使用 `claim_only` 模式验证队列和状态，再评估是否开启受控执行；
9. 最后恢复 MCP 客户端连接和反向代理。

## 路径注意事项

WSL 的 `/mnt/c/...`、Docker Desktop 内部路径和原生 Ubuntu 路径不能直接混用。配置中的绝对路径必须改成新机器实际路径。
