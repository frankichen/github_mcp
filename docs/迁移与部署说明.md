# MCP 服务迁移与部署说明

本文面向从 Windows/WSL 迁移到原生 Ubuntu 的场景。

## 迁移前

- 保存源码、`go.mod`、`go.sum`、Python requirements 和示例配置；
- 单独备份生产数据库、报告和运行数据；
- 单独备份 Secret，但不要将 Secret 放进 Git 仓库；
- 记录服务端口、域名、反向代理路径和 systemd 服务名；
- 记录 MCP 客户端使用的远程 URL、鉴权方式和协议版本。

## 原生 Ubuntu 上的恢复顺序

1. 安装 Git、Go、Python、Docker 和反向代理；
2. 克隆本仓库；
3. 为每个服务创建独立运行用户和目录；
4. 从 Secret 管理系统注入环境变量；
5. 恢复数据库、报告和行情缓存；
6. 启动服务并执行 `/healthz`、`tools/list` 和代表性 `tools/call`；
7. 最后再把 MCP URL 接回 Codex 或其他客户端。

## 路径注意事项

WSL 中的 `/mnt/c/...`、Windows 用户目录、Docker Desktop 内部路径和原生 Ubuntu 路径不能直接混用。配置中的绝对路径必须改成新系统的实际路径。

## 运行检查

```bash
curl -fsS http://127.0.0.1:8765/healthz
curl -fsS http://127.0.0.1:8090/healthz
```

确认日志中没有 Token、Authorization Header 或数据库凭据后，再开放反向代理。
